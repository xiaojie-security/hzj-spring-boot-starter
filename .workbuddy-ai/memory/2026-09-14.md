## 第二轮重构：自动装配改为纯 Provider-Bean 驱动（同日）

### 需求
移除全部基于配置文件的自动装配开关与 properties 兜底，改为「没有对应的 Provider Bean 就不注入」。

### 改动
1. **删除 properties 兜底**
   - 删除整个 `com.hzj.wechat.properties` 包（9 个类，含 `WechatMerchantProperties` 及其子类 `WechatPaymentProperties`/`WechatTransferProperties`）。
   - 删除 8 个 `Properties*ConfigProvider` 实现类（access / h5launchapp / opensdkshare / payment / qrcode / subscribe_message / transfer / virtual）及其空 `impl` 目录。
   - 删除 `config/WechatConfiguration.java`（其唯一职责就是注册这些 properties Provider + `@EnableConfigurationProperties`）。
   - 保留：8 个 `XxxConfigProvider` 接口 + 8 个 `XxxConfig` 实体（这是使用方要实现的抽象）。
   - 源码数 266 → 249。

2. **条件注解：`@ConditionalOnProperty` → `@ConditionalOnBean`**（全仓已无 `ConditionalOnProperty` / `EnableConfigurationProperties`）
   - 单 Provider 依赖：`@ConditionalOnBean(XxxConfigProvider.class)` —— Access、OAuth2、OpenSdkShare、Payment、Profitsharing、Transfer、XcxOAuth。
   - 需要凭据服务 + 自身 Provider：`@AutoConfiguration(after = WechatAccessConfiguration.class)` + `@ConditionalOnBean({WechatAccessTokenService.class, XxxConfigProvider.class})` —— H5LaunchApp、SubscribeMessage、VirtualPayment、XcxQRCode。
   - 仅需凭据服务：Ad 配置 `@ConditionalOnBean(WechatAccessTokenService.class)`。

3. **收敛兜底 WechatAccessTokenService**
   - 原先 ad / subscribe-message / virtual-payment / xcx 四处各注册一份兜底 Bean，现统一收敛到 `WechatAccessConfiguration` 一处（条件 `@ConditionalOnBean(WechatAccessConfigProvider.class)`）。
   - 其余模块用 `@AutoConfiguration(after = WechatAccessConfiguration.class)` 保证顺序。

4. **拆分 WechatXcxConfiguration**（一个类里两个不同 Provider，类级条件无法表达）
   - → `WechatXcxQRCodeConfiguration`（条件 `WechatQrCodeConfigProvider` + 凭据服务）
   - → `WechatXcxOAuthConfiguration`（条件 `WechatAccessConfigProvider`）
   - Bean 方法名 `wechatXcxOAuth2Service` 更正为 `wechatXcxOAuthService`。

5. **imports 与测试**
   - `AutoConfiguration.imports` 移除 `WechatConfiguration`/`WechatXcxConfiguration`，新增 `WechatXcxOAuthConfiguration`/`WechatXcxQRCodeConfiguration`。
   - 重写 `WechatConfigurationTest`：8 个用例，覆盖「无 Provider 时不装配任何服务且不启动失败」「仅有 access Provider 时只装配 token/OAuth/ad」「缺 Provider 不装配」「双 Provider 装配」「用户自带 Bean 时 Starter 退让」。

### 结果
- `mvn -o clean test` → BUILD SUCCESS，249 源文件，Tests run: 8, Failures: 0, Errors: 0。

### 测试写法经验（重要）
- 测 `@ConditionalOnBean` 必须用 `AutoConfigurations.of(...)` 注册被测自动装配类 + `withUserConfiguration(ProviderConfig.class)` 提供 Provider Bean。
- 原因：`@ConditionalOnBean` 在**用户配置类**中解析顺序不可控，若 Provider 在另一个用户配置里、解析顺序靠后，条件会误判为不满足。自动装配类始终在用户配置之后处理，条件才可靠。
- 另注意 `ApplicationContextRunner.withBean(...)` 走 `ApplicationContextInitializer`，注册时机更早，也可用于验证 `@ConditionalOnMissingBean` 退让。
- 单方法接口（如各 ConfigProvider）可直接用方法引用/λ 造 Bean，无需 Mockito。

### 遗留提醒
- 使用方接入方式已变化：现在必须自行声明 `XxxConfigProvider` Bean（例如从数据库/Nacos 读取），否则对应能力不会装配。starter 不再读 `application.yml` 的 `wechat.*` 配置。
- 同一 workspace 下还有 ai / alipay / aliyun / amap / elasticsearch / redis 等多个 starter。

### 关键判断：redis 是「混合模块」，不能加类级条件
`RedisCoreConfiguration` 里既有不依赖 Provider 的 Bean（`redisTemplate`），也有依赖 `DistributedLockConfigProvider` 的 Bean（`redissonClient`、`redisLockService`）。因此：
- **不能**加类级 `@ConditionalOnBean`，否则 `redisTemplate` 也会被一起关掉。
- 改为按 Bean 方法加条件：`redissonClient` / `redisLockService` 原本已有 `@ConditionalOnBean(DistributedLockConfigProvider.class)`；
- **额外给 `redisCacheService` 补了 `@ConditionalOnBean(DistributedLockConfigProvider.class)`** —— 它的构造参数里有 `RedisLockService`，若不补条件，无 Provider 时会因找不到 `RedisLockService` 直接启动失败。这是本轮发现的潜在缺陷。
- `redisDelayQueueService` 保持 `@ConditionalOnBean(RedissonClient.class)`。

- **elasticsearch、redis 的 Redisson 现在是无条件装配**（既无 Provider 条件也无 `@ConditionalOnProperty`）。含义：

- `RedissonConfiguration` 类级加 `@ConditionalOnProperty(prefix = "spring.redis.redisson", name = "enable", havingValue = "true")`。
  **注意**：这是全仓唯一保留 `@ConditionalOnProperty` 的地方，且是用户明确要求的语义（此前用户要求移除的是「用它替代 Provider 条件」的用法）。
- 连锁处理（关键，否则默认关闭时会启动失败）：
  - `RedisCoreConfiguration` 改为 `@AutoConfiguration(before = RedisAutoConfiguration.class, after = RedissonConfiguration.class)` —— 必须显式声明 `after`，因为自动装配在无序时按类名排序，`RedisCoreConfiguration` < `RedissonConfiguration`，不声明 `after` 会导致 `@ConditionalOnBean(RedisLockService.class)` 先于 Redisson 求值而永远不成立。
